_2026-06-04 — **Cross-SDK `exact`-payment wire correctness: Python + TypeScript signers fixed, Go escrow signing shipped, Rust proxy 402-parse bug fixed — four PRs merged, all SDK-only.** The live gateway verifier has required SPL **`TransferChecked` (ix 12)** for `exact` USDC payments since `e4f0db45` (so the USDC mint is on-chain-verifiable), but two SDK signers were still emitting plain **`Transfer` (ix 3)** and silently failing verification in production. [#474](https://github.com/solvela-ai/solvela/pull/474) shipped **Go** SDK native x402 escrow-deposit signing — byte-exact against the canonical golden vector and capability-gated via a `SchemeCapable` interface so `findCompatibleScheme` never hands the signer a scheme it can't fulfill (the silent mis-route the `solvela-x402` skill warns about). _2026-06-02 — **Deterministic settlement rejections now surface as non-retryable; deployed to production.** Closes the **Open** item flagged in the 2026-06-01 escrow-mint note. The gateway had reported hard on-chain rejections (e.g. Anchor `ConstraintAddress` 2012 / `0x7dc`) as a transient `"Payment transaction could not be confirmed. Please retry."` — a dead end, since the same signed tx can never confirm, wasting an agent's tokens on retries. Root cause was two compounding bugs ([#445](https://github.com/solvela-ai/solvela/pull/445), commit `ba735a1c`, closes [#435](https://github.com/solvela-ai/solvela/issues/435)): (1) `is_already_processed_error` matched bare JSON-RPC `-32002`, which is `SendTransactionPreflightFailure` — the umbrella code for **all** preflight rejections, not just already-processed — so a deterministic rejection was swallowed as an idempotent resubmission, then dead-ended in the 30s confirmation poll and surfaced as a timeout; now matched on the "already processed" message text only. (2) the route flattened every failed settlement to the same retry message, discarding the captured program error. The fix adds `SettlementFailureKind` (`Rejected{program_error_code}` / `Timeout` / `Submission`) on `SettlementResult`, classified by a pure `classify_settlement_error` in `crates/x402/src/solana_rpc.rs`; the gateway (chat route + A2A handler) maps `Rejected` to a non-retryable message carrying only the numeric program code (never raw RPC internals — GHSA-cgqx-mg48-949v), while `Timeout`/`Submission` stay retryable. Applied across escrow, direct (`exact`), and A2A settlement paths — the direct path previously propagated send failures as `Err`, bypassing classification entirely. Money-path review ran two rounds (`rust-reviewer` + `silent-failure-hunter`): round 1 caught the direct-scheme `Err`-bypass plus `Custom`-anchor/`u32` issues, round 2 caught the A2A gap and a missing escrow-confirmation log — all fixed in-branch. Tests green at merge: protocol 21, x402 145, gateway 629 lib + 138 integration; `cargo clippy --workspace --all-targets --all-features -D warnings` clean. **Deploy:** gateway **v331 → v333** (Fly.io `solvela-gateway`, region ord, rolling strategy — zero downtime, both machines updated, Fly smoke + `/health` checks passed; `{"status":"ok"}` at `https://solvela-gateway.fly.dev/health`); image `deployment-01KT31ETKQC5R9GJQXRW6XWSZ5`.
